# Rubric: notes for the agent working on this repo

An open, git-native format for exam-prep question banks: a question is a Markdown
file with YAML frontmatter, and the per-choice rationale is the unit of value.
Apache-2.0, by ObiLabs; it is also the quiz engine behind training content in
Aegis. Read `README.md` (what and why), `docs/FORMAT.md` (the spec) and
`ROADMAP.md` before changing anything about the format.

## Layout

- `src/rubric/`: the Python reference parser, bundle/blueprint checker and CLI
  (`rubric` → `rubric.cli:main`). One runtime dependency, PyYAML. Python 3.9+.
- `web/`: the JavaScript port and the browser playground (`index.html`), with
  `examples.bundle.js` generated by `node web/build_examples.cjs`.
- `tests/`: pytest, including `tests/conformance/` — the shared fixtures both
  implementations must agree on.
- `examples/`: example corpora; each `manifest.json` must pass `rubric validate`.
- `scripts/`: `generate.py`, `verify.py` and the authoring specs.

## Rules

- **The Python parser is the reference implementation.** The JS port in `web/`
  must stay byte-for-byte in step with it; CI (`web-parity`) fails when it
  drifts. A format change lands in `docs/FORMAT.md`, the Python parser, the JS
  port and the conformance fixtures in the same pull request.
- The format is public and other people's banks depend on it: a breaking change
  to the frontmatter or the bundle manifest needs a version bump and a note in
  `ROADMAP.md`, never a silent redefinition.
- Keep the dependency list at one. New runtime dependencies need a reason that
  survives "someone will install this to parse a Markdown file".
- Question *content* lives in the private `obilabs/rubric-banks` repo. Only
  illustrative examples belong here; never paste licensed exam material.
- Tests: `python -m pytest -q`, plus `npm test` in `web/` for the port. Both run
  in CI on Python 3.9 / 3.11 / 3.13.

- **No AI co-author trailers** (`Co-authored-by: Claude …`) and no "Generated

  disclosed once, in the README. `.claude/settings.json` here turns that
  attribution off; keep it.
- Work on a branch and land it through a pull request. Never commit to,
  force-push or `git branch -f` `main`.
- This is a public repository: commit messages, PR titles and PR bodies use
  routine engineering wording. Never narrate a security finding in public.

## What never goes in the repo

Secrets, tokens, `.env` files, real person or tenant data in fixtures (use
`example.com`), and absolute paths containing a username — they break
portability and leak the developer's account name. The shared hygiene workflow
(`.github/workflows/hygiene.yml`) checks all of this on every push and pull
request.

The org-wide engineering rules are canonical in the private `obilabs/north-star`
repo (`PRINCIPLES.md`); this file is the repo-specific form of them, not a copy.
